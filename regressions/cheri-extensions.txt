# CHERI review of every RISC-V extension property the QEMU under test offers
# (checked by utils/scripts/cheri-ext-review.py, gate stage 1).
#
#   <property> allowed|refused   # why, and which test covers it
#
# "refused": the CHERI extension policy must refuse it (it bypasses
# capability checks). "allowed": accepted on CHERI CPUs. An extension that
# loads, stores, changes addresses, control flow or PTE/privileged state may
# only be "allowed" once its CHERI behaviour is implemented and tested.
# When a QEMU rebase adds an extension, the gate fails until it is listed.
